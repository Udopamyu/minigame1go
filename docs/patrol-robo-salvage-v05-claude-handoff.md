## 0. コンセプト／最新版の解釈

**一言で：装備を奪って強くなる、地形・遮蔽物を利用した高機動3Dメカ戦闘。**

- **PATROLの長所**：シネマティックな3D表現、機体・カメラの手触り、立体的で見通しのよい画面。初期の「完全な戦闘機型自由飛行」をそのまま採用するわけではない。
- **ロボサルベージの長所**：武器・装甲・脚部・コアの4部位、敵の装備サルベージ、分岐ステージ、GOLD／SPによる成長、ボス、エンドレス。
- **最新方針（2026-11-18の本人合意）**：常時飛行する空中戦より、**地面近くをホバーし、必要時だけ上昇・下降する**アーマード・コア風の3D戦闘にする。敵AI、地形、遮蔽物、カメラを作り直す。
- **最重要の体験**：画面下寄りに自機、中央付近に敵機＋レティクル。**プレイ中に両機の位置が常に理解でき、気持ちよく横移動・前後移動・回避できる**こと。参考としてユーザーがアップロードした「巨大な敵を中央に捉え、自機は下側に見えるメカ戦闘スクリーンショット」をClaude側にも再添付するのが望ましい。
- 世界観：硬質・精密・飛行可能なメカ。戦車形状は避ける。スター・ウォーズのXウィングやアーマード・コアは**シルエット・メカ密度の方向性の参考**であり、既存IP固有デザインをそのまま複製する指示ではない。

## 1. 指示の優先順位と注意

1. **本書の最新ユーザー合意**を最優先する。v0.1〜v0.4の旧仕様と矛盾すれば、本書を採用する。
2. GitHub `Udopamyu/minigame1go` の `AGENTS.md`、`docs/game-development-guide.md`、`specs/robo-salvage.md` は開発・保存・品質の基準。ただし2D固有の操作（移動しながら手動照準等）を3D版へ強制しない。
3. 既存のv0.5コードは**出発点**であり、意図した仕様がすべて正確に動作している保証ではない。コードよりも実プレイと本人が示した構図を優先して調整する。
4. `PATROL_Last_Light.html` は描画・雰囲気・操作感の参照であって、仕様としては常時前進を継承しない。
5. 旧v0.3操作調整JSONの数値は**ユーザーが過去に選択した基準値**。v0.5では低空ホバーに変更したため、速度・カメラなど旧飛行機型のパラメータには、そのまま運動方程式を決める効力を持たせない。調整パネルと設定共有の仕組みは維持する。
6. **実装済み／動作を確認した／未検証／今後の要求**は区別して報告する。「見た目が表示された」だけで遊びが完成したと扱わない。

## 2. 戦闘中の画面・カメラ・ロックオン【最優先】

### 構図
- 自機は**画面下側（中央〜下1/3）**に必ず見える。大きすぎて視界を占領しない。
- 敵機は**画面中央付近の追従対象**として見える。照準レティクルと敵表示が自機と重ならない。
- 自機と敵機の距離や相対高度が変わっても、視野角・ズーム距離・注視点を動的調整して**可能な限り両機を画面内**に収める。追従のための唐突な瞬間回転・ズームは抑える。
- 画面中央の**射撃用レティクル**と、敵に付く**ロックオンマーカー**を別に描く。HUDは極力文字なし。枠の太さ・色・動きで状態を示す。
- 敵の移動をカメラが自動追従する。敵を見失い、現在地がわからなくなる挙動は不可。右スティック操作中は一時的に操作を尊重し、離したら滑らかに敵追従へ戻る（追従枠内での遊びを残す）。
- 敵が障害物の陰に入れば3Dの遮蔽は維持し、画面上の方向表示と視認できるロック状態の区別で所在を知らせる。**遮蔽を無視して射撃してはいけない。**

### 射撃
- 通常は自動射撃ON。**追従しているだけでは撃たない。敵が中央レティクルの判定域に入り、射線が通り、射程内である時だけ発射**する。
- 自動射撃のON/OFF、任意の手動射撃ボタンも調整可能にする。ON/OFFと手動トリガーの判定を曖昧にしない。
- ロック判定は見た目のスクリーン座標、ゲーム世界の3D位置、障害物との射線遮断を一致させる。レティクル中央に見えるのに撃てない／敵が横にいるのに撃てる、といった矛盾がないこと。
- 敵追従・ロック成立・攻撃実行は**別の状態**として実装する。

## 3. 移動操作【最優先】

| 入力 | ユーザーが希望する動作 |
| --- | --- |
| 左スティック左右 | 視点方向基準で**左・右へ平行移動**。勝手に旋回しない |
| 左スティック前後 | 視点方向基準で**前進・後退** |
| 左スティックを離す | 慣性を短く収束させ、**空中で静止**。常時前進しない |
| 右スティック左右 | カメラを右／左へ向ける。操作方向は直感どおり |
| 右スティック前後 | 前へ倒すと上を向く、後ろへ倒すと下を向く（旧版の反転問題を再発させない） |
| 上を向いて前進 | 視線方向に沿って上昇できる |
| 下を向いて前進 | 視線方向に沿って下降できる |
| 上昇・下降操作 | 必要に応じたホバーブーストで高さを変えられる |
| ダッシュ／ブースト | 回避・機動用。装備による性能差を活かす |

- 主な戦闘は低高度で行い、空へ延々飛び去る構造にしない。上限高度や下降時の接地処理は自然に見えるよう調整。
- 基本は**地形近傍のホバー**。カメラの向きと移動方向の関係が明快であること。
- PC暫定操作：WASD移動、矢印でカメラ、Shiftダッシュ、Space上昇、C下降、T調整パネル。スマホは左右の仮想スティック。操作割り当ては快適さのため変更可だが、**意味は維持**。
- 旋回方向の逆転、手を離しても飛び続ける、画面から自機が消える現象は禁止。

## 4. 戦闘環境・フィールド【最優先】

- **同色の平坦な床の繰り返しではなく**、マップごとに地形の高低・建造物・障害物・距離感を明確に作り込む。
- 環境8種は既存試作に荒野、砂漠、雪山、山岳、市街地、川、スタジアム、夜間。特に雪山＝山脈・峡谷、砂漠＝砂丘・岩山、市街地＝高層建築・立体道路、山岳＝尾根・谷、夜間＝発光施設・工業地帯など、**戦い方に違いが出る立体構造**を作る。8種を単純に背景色だけ変えて増やさない。
- 山・岩・建物には**実際の衝突判定**が必要。衝突自体で必ずダメージを与える必要はない。
- **遮蔽物に隠れると敵弾が遮られ、攻撃を避けられる**ことが必要。見える地形と衝突・遮蔽の判定は同じデータから生成する。ミサイル・ビーム等についても遮断や武器固有の例外規則を明確にする。
- 地形に合わせた回避経路、近接・中距離・遠距離戦術が成立する。
- 広さはv0.5付近の感覚を出発点とする（ユーザーは厳密な距離を指定していない）。**マップがループしているのか、行き止まりなのか不明**にならないよう、外周・境界を遠景の壁や地形、緩衝措置、ミニマップ等で自然に示す。突然不可視の壁に当たるだけにしない。
- フィールドオブジェクトは装飾と当たり判定で位置や高さが食い違わないようにする。地面に埋没したり、前後関係が逆転したりする描画は不可。

## 5. 敵AI・戦闘【高優先】

- 旧版は敵がプレイヤーの**後ろにぴったり張り付き、動きが不自然**だった。改善が必須。
- 役割に応じて接近、武器の適正射程維持、横移動、距離が近すぎれば後退、遮蔽物を使う行動、側面への回り込みを切り替える。
- 追跡一辺倒にならないよう、状態・クールダウン・経路選択を設計する。障害物や境界で詰まれば回避／経路再検討を行う。
- **まず1対1の戦闘を確実に成立**させる。3D化だけで敵を増やさず、距離・射線・カメラ構図を優先する。
- 敵の弾も3Dの射線と遮蔽規則に従う。敵機自体は自機よりやや赤系統で識別しやすくする。
- ゲームとして成立するよう、プレイヤーが「敵を見て、回避し、遮蔽物に隠れ、照準を合わせて反撃する」サイクルを持たせる。

## 6. 機体グラフィック・弾・演出【高優先】

### メカ造形
- 戦車っぽい塊ではなく、**航空・宇宙機に見合う推進器・翼・姿勢制御機構・関節・装甲パネル**を備えた精密なメカにする。人型・戦闘機型の融合もよい。
- 武器、装甲、脚部、コアは**色違いだけにしない**。シルエット、砲身、推進器、脚の構造、動作を変える。
- 機体は画面を覆いすぎない。以前のv0.4設定 `modelScale:1.4` はユーザー希望の過去値だが、画面占有を避ける**最終的な投影サイズ**を優先する。

### 解像度
- 重いモザイク拡大、粗すぎるドット、ちらつきは疲れるため避ける。**より細かいドット調／高解像度の3D**へ。主役の輪郭と背景の遠近を見分けやすくする。
- GPU性能を確認し、描画解像度を調整可能にする。画質向上とフレーム安定性の両立。

### 武器ごとの発射エフェクト
- 実装済みの8系統を継承：パルス、散弾、レールランサー、誘導ミサイル、ニードル、バースト、スラグ、リコシェット。
- レールランサー＝細い強いビーム／残光、誘導弾＝**実体のあるミサイル・尾翼・噴射炎・曲がる煙軌跡**、ニードル＝細い高速弾、散弾＝拡散が分かる粒子、スラグ＝重い大型弾、反射弾＝跳ね返りが見える軌道、等。
- 発射→飛行→着弾まで視認できる。命中時は火花・爆発・短いヒット反応を与える。エフェクトで敵機や照準を隠しすぎない。
- なるべく同じ弾体の色違いだけで済ませない。

### 勝利／敗北
- 旧2D決着演出は3D派生版へ持ち込まない。**約2秒**で、勝利時は敵機、敗北時は自機が3D空間内で破損し、装甲・腕・脚・砲などがバラバラに飛散する。火花、煙、爆発、カメラ演出を伴い、結果画面へ遷移する。
- ただの2D四角形が散るだけでは目標未達。可能な限り機体のメッシュ部品が外れる破壊演出を目指す。

## 7. マップ選択・強化・ゲーム進行【既存の長所を保持】

- ロボサルベージの**3択の分岐ルート**を継承。暗い黒基調で洗練されたすごろく風UI。
- 現在のマスに**デフォルメ自機**。選択可能な次の3マスを明瞭に、その先の分岐は薄く表示。全体を見渡す機能があってもよいが、今決める3択が目立つこと。
- 戦闘／強敵／イベント／ショップ／休憩／資材庫／ボスに選択理由がある。ステージ選択時は戦闘を停止する。
- **4部位**：武器・装甲・脚部・コア。敵を倒し、装備1つを奪うか解体でGOLDを得て、ショップ・回復・強化に使用。
- **永続成長**：SP研究、初期武器の解放、最高到達記録などは保持。敗北でラン中装備とGOLDは失う、SPと永続解放は保持（2D基準）。既存保存データを勝手に消去しない。
- **ボス／エンドレス**：初回の約10マス＋ボスを経て、装備と強化を持ち越してエンドレスに進む。以降敵が強化され、一定間隔でボス。現行2Dでは初回後に9探索＋1ボス、エンドレスにGOLD限界突破がある。3D版への統合時は数値と挙動を照合。
- **コア4種**：バランス、パワー、スピード、タクティカル。実装値の例：パワー攻撃+25%／移動-15%、スピード移動+22%／攻撃-15%、タクティカル弾倉1.5倍／装填-20%。ダッシュCTを含め、実際の操作に反映する。
- 武器やショップ、成長のUIは戦闘HUDと分離する。HUDはアイコンとゲージを優先、詳細は格納庫・メニューで表示。

## 8. UI・音・操作調整ツール

- **最重要デザイン規範：通常のプレイ画面には極力文字を表示しない。** 長い説明・状態ラベル・常設の操作ガイドは排除。アイコン、ゲージ、形、音、短い演出で情報を伝える。
- 調整画面は例外として詳細文字・数値を使ってよい。実験用パネルを通常の遊びから明確に分離する。
- **ゲーム中に設定を調整**できるツールを残す：移動速度、加速度、追従速度、カメラ距離・高さ・オフセット・FOV・自機サイズ、追従枠／射撃判定、解像度、武器・ステージ、自動射撃ON/OFF、手動射撃。
- 値は即時反映、リセット、保存、**JSONエクスポート／コピー**ができること。過去にユーザーがこの仕組みを使い設定値を指定している。
- PC・スマホ縦横を考慮し、左右スティックやボタンが重なったり自機・敵・照準を隠したりしないこと。
- 発射・ブースト・命中・警告・破壊に効果音。可能ならチップチューン／SF風BGMをフェード付きで切替（音声自動再生制限に配慮）。

## 12. 開発順序・受け入れ条件

### 第1段階 — 操作とカメラ（最優先で実プレイ検証）

- [ ] 左スティック前後左右が視点基準で直感通りに動く。無入力で止まる。前進しながら上を向くと上昇できる。
- [ ] 自機は下側、敵は中央付近で、両機が画面から頻繁に消えない。距離変化で自然にズーム。
- [ ] 敵カメラ追従と右手の自由操作が衝突せず、手を離すと自動追従へ戻る。
- [ ] 中央レティクル内＋射線OKでのみ発射。ロック外・遮蔽中は停止。

### 第2段階 — 地形とAI

- [ ] 山・谷・建物等を**実際に飛び回れる立体構造**にし、各環境の体験差が分かる。
- [ ] 障害物にぶつかり／隠れられる。敵弾が遮蔽物を貫通しない（貫通武器は例外ルールを定義）。
- [ ] 境界が分かる。敵は後ろへ張り付き続けず、近・中・遠・横移動を使い分ける。

### 第3段階 — グラフィックと武器演出

- [ ] 機体は戦車ではなく、推進器と航空的シルエットを持つ細密メカ。装備による外見差が分かる。
- [ ] 地形・背景・機体は粗い拡大ドットより高精細で、画面が見やすい。
- [ ] 弾体・弾道・着弾表現が武器種で識別できる。ミサイルは実体＋煙、レールはビーム。
- [ ] 勝敗時は約2秒の**3Dパーツ分解**とリザルト遷移が正しく発生する。

### 第4段階 — 既存進行の統合

- [ ] 分岐すごろくの現在地・次3マス・先の薄いマスが明快。
- [ ] 戦闘→報酬／ショップ→次ステージ→ボス→エンドレスで一周できる。
- [ ] 4部位交換・GOLD／SP・永続強化・敗北時の扱いが一致し、セーブが消えない。
- [ ] PC・スマホでHUDとスティックが被らず、必要最低限の文字だけで理解できる。

### 検証手順

- 修正のたびに**ブラウザを起動して本当の戦闘状態に進み、スクリーンショットを保存**する。格納庫や静止初期画面だけでOKとしない。
- 撮影した画像では、自機・敵・レティクル・地形の前後関係、弾体の見え方、見切れ、UI重複、水平線の矛盾を目視点検する。
- 少なくとも「無入力」「前後左右移動」「高低差」「敵接近／側面移動」「遮蔽物越し」「ロック中／ロック外」「雪山」「市街地」「夜間」「勝敗」「スマホ縦・横」で状態を切り替える。
- WebGL2が使えないブラウザでは「代替描画のみ確認」と表記し、**別環境でWebGL2を必ず検証**する。プログラムの静的検査とブラウザ実動作を混同しない。
- 仕様を変更する時は該当部分だけを直し、正常な他機能を壊さない。完成時は単体HTML、再編集用ソース、変更履歴、検証内容と未確認点をセットで納品。
