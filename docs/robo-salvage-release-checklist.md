この記録は技術的な準備と「公開してよい」の判断を分ける。ユーザーの明示的な公開承認前に `main` へマージ、GitHub Pages公開、X投稿をしない。

## リリース方式

- 無料・広告なし。単一ファイル `games/robo-salvage/index.html` をGitHub Pagesに配信する。
- JavaScript/CSSはHTML内に埋め込み済み。外部のCDN、画像サーバー、分析サービス、アカウント連携は不要。
- `main` にマージした後、GitHub Pagesの設定に従い `games/robo-salvage/` のURLを開いて配信状態を確認する。**事前にURLが動作すると断言しない**。既存の作品・サイトを破壊しない。
- 公開後も修正が必要なら別PRを作り、検証→人間の確認→マージの順番を維持する。

### 公開判断で特に見ること

1. 最初の2〜3戦の強さ、被弾率、リロードと間合いの戦術が機能しているか。
2. 初回ボスを倒して機体を引き継げること。エンドレス10ステージごとのボス、無制限の限界突破、敗北時のステージと各マス内訳を確認する。
3. 部位変更が機体シルエットと数値ステータス・コンボ表示に反映され、戦利品画面が読みやすいか。
4. 敗北後のSP獲得・購入・40 SPで初期武器解放が再起動後も維持されるか。
5. ブラウザ更新で進行中の周回は再開しない仕様であることを、プレイヤーが理解できるか。

## 公開オペレーション（最終承認後）

1. PR #12 の**最新コミット**で Actions がすべて成功していることを再確認。
2. 人間の試遊内容・重大不具合なし・公開可否を記録。
3. 明示的な承認が得られたら、PR #12 をレビュー可能状態にし、`main` にマージ。
4. GitHub Pages の反映を待ち、**公開URLを実際に開いて**PC／スマホの初回起動・戦闘・保存をスモークテスト。
5. 公開URLをREADMEと投稿草案に反映。公開後の問題に備え、直前コミットSHAを控える。
6. 実プレイ動画（10〜20秒）を作成・視聴確認し、X投稿文とURLを人間が確認して**手動投稿**。URL／動画未確認での投稿はしない。
