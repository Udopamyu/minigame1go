# MiniGame1GO 4部門ワークフロー

| 部門 | 担当 | 成果物 |
| --- | --- | --- |
| 統括 | 企画、テーマ選定、品質の最終判断、公開判定、X投稿草案と効果測定 | specs/<id>.md / 投稿履歴 |
| ゲーム制作 | HTML5実装、UIと操作、基本単体検証 | games/<id>/index.html |
| ゲーム評価 | 実ブラウザテスト、操作性、視認性、クリア可能性・バランス評価 | evaluation/<id>/test-results.json / review.json |
| 動画制作 | 合格版の実プレイを10〜20秒で録画・編集、動画の技術検証 | videos/<id>/gameplay.mp4 / recording.json / 投稿草案 |

1. 統括が仕様と成功条件を定義する。
2. ゲーム制作がビルドを提出する。
3. 評価部門がブラウザで実際に操作し、検証と不具合票を提出する。
4. **基本動作合格時のみ**動画部門が実プレイを録画する。
5. 統括がゲーム内容・動画・安全性・公開URLをレビューする。人間による面白さ/10ステージ進行の評価は省略しない。
6. ゲームのデプロイとX投稿は独立の工程。Xには自動投稿しない。

## 自動化の境界
GitHub Actionsで「ゲーム評価 → 評価レポート → 実プレイ動画」を自動実行する。
Pythonの役割別スクリプトと成果物の受渡しを最小構成とする。現段階では別々の常駐LLMエージェントを立てたものではない。
成果物がない場合や評価で落ちた場合は成功を報告しない。
